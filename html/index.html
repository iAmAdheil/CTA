The Orchestrator Cycle — one stateless tick

The orchestrator is an LLM agent (the /orchestrator skill), not a while True loop. An external driver (cron / /loop / file-watcher / you) invokes it; it reads file state, reacts to transitions, writes state, and exits. Crashes are free — the next tick replays from disk. Click a step to expand.

Source of truth is on disk. orchestrator-state.yaml + the task YAML files under tasks/{backlog,in-progress,review,done}/. The kanban boards are a derived projection — never load-bearing.

Kanban Boards — the human-glanceable projection

Three persistent Obsidian boards in docs/_kanban/. The orchestrator moves one card at a time (idempotent "ensure card C in column COL") — it never regenerates a board, so your manual edits survive. Card moves are gated into worker teardown and anchored on active_workers for crash-safety.

Board can drift from task status: — it's a second copy of state with no self-healing regeneration. Accepted tradeoff; the orchestrator minimizes drift by moving cards inside the transitions it already processes, and the reconcile step re-asserts the column for in-flight work.

Files & Fields — the control plane

Everything dynamic lives in files. Task files are control-plane state (gitignored, in the main worktree, read by absolute path per ADR-001). Field ownership is disjoint so writers never race.

Agents — who does what

The orchestrator is the only sequencer. Every other agent is spawned by it: synchronous claude --print for fast deciders, async tracked tmux sessions for slow doers.
